# 画面规格

> 只定「每个画面要显示哪些数据、能做哪些操作」，不定配色、排版细节（10/21 起照最伟大的书卷风格设计）。
> 这里定的字段，就是数据库与 API 回传格式的依据；实际回传格式见 [09_接口文档](09_接口文档.md)。
> 示意图的例子是 10/16 的双非计算机；参赛版 10/22 起限定光华，画面上的例子都改成光华情境。

## 搜索结果页（搜索＋筛选＋分岔）— 2026/10/16 定

像电商搜索：打「外套」马上出所有外套，再用旁边的条件筛。

```
┌───────────────────────────────────────────────────────────────────────────┐
│ 🔍 [ 双非计算机 GPA3.4 大三，保研还是考研                ] [搜索]         │
└───────────────────────────────────────────────────────────────────────────┘
┌─ 筛选条件 ──────────┐ ┌───────────────────────────────────────────────────┐
│ 决策类型             │ │ [全部 19] [跟你最像 6] [起点比你好 8] [跨专业 5] │
│ ☑ 考研 (15)          │ │ 走了哪些路：考研 11 ／ 保研 6 ／ 工作 2          │
│ ☑ 保研 (6)           │ │ 成功 12 ／ 失败 5 ／ 转向 2                      │
│ 学校层级             │ ├──────────────────────────────────────────────────┤
│ ☐ 985 (0)            │ │ 🎯 跟你最像：双非计算机 GPA 3.3–3.6（6 人）      │
│ ☐ 211 (8)            │ │    考研 4／保研失败转考研 2                      │
│ ☑ 双非 (11)          │ │    👤 学长 A｜考研 → 上岸北大 ✅                 │
│ 专业                 │ │       为什么是他：同是双非计算机、大三才决定     │
│ ☑ 计算机 (14)        │ │    👤 学姊 B｜保研失败 → 考研 ✅                 │
│ 结果                 │ │                     [看这群全部 6 人]            │
│ ☐ 成功 ☐ 失败 ☐ 转向 │ ├──────────────────────────────────────────────────┤
│ 年级 ／ 年份         │ │ ⬆ 起点比你好：211 计算机（8 人）                 │
│                      │ │    保研成功 5／考研 3                            │
│                      │ │    👤 学长 C ⋯   👤 学长 D ⋯                     │
│                      │ │                     [看这群全部 8 人]            │
│                      │ ├──────────────────────────────────────────────────┤
│                      │ │ ↔ 跨专业来的（5 人）⋯                            │
└──────────────────────┘ └──────────────────────────────────────────────────┘
  ▸ 检索过程（展开看 agent 每一步）
```

**已定：**
- 读者打自然语言（「双非考研」），**马上出结果**，没有必填、不先填表
- **AI 读懂搜索字，自动勾好对应的筛选条件**（双非、考研）；读者可再勾选或取消，结果即时变化
- 每个筛选条件旁显示**数量**
- 筛选条件：决策类型、学校层级、专业、结果（成功／失败／转向）、年级、年份
- 结果上方显示「**走了哪些路**」与成功／失败／转向人数，做成**可以点的筛选**（点「考研」就只剩走考研的人）；人少时照实写人数，不换算百分比
- **分群呈现＝从上往下排＋分页标签＋筛选条件**（2026/10/16 定）：
  - 「全部」标签（缺省）：每一群一个区块从上往下排，跟读者最像的群排最上面；每群显示统计＋**2 位代表人物**＋「看这群全部 N 人」
  - 点某一群的标签（或「看这群全部」）：只显示那一群，列出全部成员
  - 左边筛选条件和「走了哪些路」套用到所有群，标签上的人数跟着变
  - 群的名称（跟你最像／起点比你好⋯）和「为什么是他」由判断 agent 产生；人数由程序算
  - **「起点比你好」另外算**（2026/10/16 定，B2）：AI 照样自动勾学校层级，主列表只有符合的人；但「起点比你好」群不套学校层级筛选（其他筛选照套），找学校层级比读者高的人，放在最下面、也有自己的标签，标「不受学校层级筛选影响」。读者是 985 或没提到学校层级时不显示
- **退路**：agent 失败或超时，没判断完的群维持关键词／rerank 版（不显示「为什么是他」）；检索过程面板写明哪几群超时（见 [03_系统架构](03_系统架构.md) 流程 B 保险）
- **推荐理由＋红绿灯**（2026/10/22）：每篇卡片附「为什么是他｜独有的点」并排＋原话（最多三行）＋一颗灯（红＝很匹配、黄＝一般、绿＝可能会想看），意思写在图例；灯晚约 10 秒到，到了群内按红→黄→绿排。主题／热门／人物页的〔AI 帮我选〕同一套
- **「跟你差在哪」改「独有的点」**（2026/10/22）：读者没讲背景时模型会拿 GPA 硬比 → 改写这个人独有的一点，不跟读者比、不用他／她，卡片上已有的 GPA 排名不算
- **筛选条件缺省折叠**，标题显示「已选 N」；「AI 理解为」标签用后端 LLM 抽到的条件（读者还没动过筛选时）

**每张人物卡的数据（＝搜索要回传的字段）：**

| 显示 | 对应字段 |
|---|---|
| 姓名／头像 | 人物 id → 人物表 |
| 背景（学校层级、专业、成绩） | 决策前状态 |
| 年份 | 决策点年份 |
| 选择 → 结果 | choice、outcome |
| 一句说明＋原话 | 判断 agent 写的「为什么是他／独有的点」（经过引用核验）、原话；非代表的卡片用推荐理由那包，都没有就不显示 |
| 红绿灯 | `/api/filters/why` 的 `match`（high／mid／low） |
| 相似度 | 排序用，不显示 |

**对数据库与 RAG 的影响：**
- 筛选条件全部是决策点既有字段，数量用 SQL 分组计算
- 「把搜索字转成筛选条件」是处境抽取（RAG 那边）；`search()` 收到「搜索字＋目前勾选的条件」，在符合条件的范围内排序回传

## 找不到结果（拒答）— 2026/10/16 定

系统找不到合适的经验时，老实说「没有」，不让 AI 自己编。做成**一个页面、三个区块**，各自符合条件就出现：

```
┌─ 目前还没有人分享过「双非医学考公失败」这样的经验 ──────┐
│ 🔧 试试拿掉一个条件：                                   │
│   [✕ 失败] → 3 人   [✕ 医学] → 7 人   [✕ 双非] → 2 人    │
│                                                         │
│ 👥 最接近的经验（相关度较低）：                         │
│   👤 学长 E｜双非医学 → 考公上岸                         │
│      跟你的差别：结果是成功，不是失败                    │
│   👤 学姊 F｜985 医学 → 考公失败                         │
│      跟你的差别：本科是 985，不是双非                    │
│                                                         │
│ 🧭 或从这里开始逛：                                     │
│   [保研] [考研] [出国] [求职] [考公] [选导师]            │
└─────────────────────────────────────────────────────────┘
```

| 区块 | 什么时候出现 | 谁做 |
|---|---|---|
| A 拿掉一个条件 | 有勾筛选条件，且拿掉某个条件后就有结果；**显示拿掉后有几人** | Ken（SQL 算拿掉每个条件后的笔数） |
| B 最接近的经验 | 有相似度够的经验、只是没有完全符合；**标出「跟你的差别」** | 同学（相似度门槛由他调；差别用规则逐栏比对） |
| C 分类入口 | 一直都在；搜索字跟升学求职无关时只剩这块加一句提示 | 同学判断「抽不出任何条件」，Ken 做画面 |

**猜你想看**（2026/10/22）：有召回、但红绿灯回来没有一篇红或黄＝库里其实没有答案 → 换成这一页（只留 C 分类入口＋D 我想看，不放 A、B），下面列「猜你想看」：只放至少对上一条条件的；一条都没对上不硬凑（例：搜「台湾」→ 只有没答案画面）。灯要约 10 秒才到，所以会先出一般分群再换成这页。

**对 RAG 回传的影响：** `search()` 没有完全符合时，要回传「最接近的经验」清单（同人物卡字段）＋每笔跟读者处境不同的字段；无关问题要回传一个标记让前端只显示 C。

## 求经验（找不到结果页的区块 D）— 2026/10/16 定

一般功能（不当创新点）：读者搜不到时，可以请处境最接近的分享者来写。

```
① 找不到结果页多一块：🙋 [我想看这类经验]   已有 3 人想知道
② 创建「求经验单」：搜索字＋勾选条件；同样的需求合并计数
③ 通知处境最接近的 5 位分享者（站内通知）：
   「有 3 位读者想知道：医学部转金融是怎么决定的？」
④ 分享者点通知 → 进写作页，主题已预先填好
⑤ 文章发布后，通知当初按过「我想看」的读者
```

**已定：**
- 读者**要登录**才能按「我想看」（有人写了才通知得到他）
- **按「我想看」的人数满 5 人才邀请分享者**，只发一次；同一人按几次都只算一次（10/17 定）
- 怎么挑 5 位：规则比对条件（决策类型、学校层级、专业、结果、年级、年份）；**一个条件都对不上的人都没有**时交给邀请 agent（07 #6）；agent 用不了取推荐数最高的 5 位
- 通知可以先记在分享者名下（还没注册的人，注册后登录就看得到）
- 只做**站内通知**（小红点），不寄信
- **①–⑤ 完整五步都做**；④ 要用到写作页（写作页定案时要包含「从求经验单进来、主题预先填好」）

**读者帐号：谁都可以注册**（2026/10/16 定）。读者要按「我想看」需要登录。

- **一套帐号、两种身分**（2026/10/16 定）：**分享者一定也是读者，读者不一定是分享者**。任何人都能用邮箱＋验证码注册成读者；只有再验证 pku.edu.cn 邮箱的人，才升级成分享者（可写文章、有人物页、可被预约）
- 读者注册和北大验证共用同一个邮件服务（寄验证码）

**数据表：**

| 表 | 存什么 |
|---|---|
| 求经验单 | 搜索字、条件、想看人数、状态（等待中／已有人写） |
| 想看的读者 | 谁按了哪一张单 |
| 通知 | 发给谁、内容、已读与否 |

## 写作页 — 2026/10/16 定

```
┌─ 写一段你的决策经历 ─────────────────────────────────┐
│ 标题 [________________________________]              │
│ ┌──────────────────────────────────────────────────┐ │
│ │（直接写）                                         │ │
│ └──────────────────────────────────────────────────┘ │
│ 💡 可以写写：当时的你、考虑过哪些路、最后怎么选、    │
│    结果如何。没走成的路也很有价值，请照实写。        │
│                                [预览]  [发布]        │
└──────────────────────────────────────────────────────┘
```

**已定：**
- **自由写作**：标题＋文章，不分段填表
- 放一段**提示文本**（不强制），鼓励写完整、写失败经验
- **不设决策类型菜单**，决策类型等全部字段都交给 AI 从文章抽出
- 从求经验单进来时，标题／主题预先填好
- **发布前确认决策点**（已做）：按〔发布〕先叫 `/api/articles/extract`，弹窗列出 AI 抽的决策点（可改每一栏、加删决策点），作者确认后才真的发布；改了标题／正文就作废重抽。改文章时一样

**对数据库的影响：** 决策点字段＝AI 要抽的字段（决策类型、学校层级、专业、年级、成绩、选择、结果、年份、原话⋯），可以先定，不用等写作页。

## 评价机制（文章「有帮到我」＋咨询评分）— 2026/10/16 定

目的：让品质看得见，并给分享者竞争感（冷启动最难的是让分享者来写）。

**① 文章：「有帮到我」＋短评**
- 文章页底部：〔👍 这篇有帮到我〕按钮＋短评（选填，200 字内）；要登录，每人每篇一次
- 文章页显示「N 人觉得有帮助」与短评列表
- 人物页显示「累计帮到 N 人」
- 首页／人物数据库：「最有帮助的分享者」排行（依累计有帮助人数）
- **评的是「有没有帮到我」，不是「这个人厉害不厉害」**——失败经验不能因为结果不好被评低

**② 付费咨询：评分＋评论**
- 咨询结束后（我的预约里状态变「已完成」），读者可给 1–5 星＋评论；每笔预约一次
- 人物页显示咨询平均星数与评论数、最近几则评论
- 参赛版没有真的金流与视频，「已完成」先由读者在我的预约按〔完成并评价〕
- **可预约时间以月为单位**（10/17 定）：分享者在咨询设置的月历点日子、勾整点（00:00–23:00 都可以，一个整点一个时段）；读者预约时在月历上只看得到还没被约走的时段，同一时段只能被约一次；平台内完成，不让双方私下联系约时间
- **付款用分享者自己的微信收款码**（10/17 定）：分享者在咨询设置上传收款码；读者在我的预约扫码付款后按〔我已付款〕，分享者收到站内通知，自己到微信核对。平台不经手钱、不验证是否真的付了
