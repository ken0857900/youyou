# 鹿鸣 PathFinder 后端接口文档

> 对应代码：`backend/app/main.py`（全部路由）、`backend/app/agents.py`（搜索 multi-agent）
> 线上：`http://47.93.125.3/api/...`　本机：`uvicorn app.main:app --port 8000`（在 `backend/` 下）
> FastAPI 自带交互文档：`/docs`（Swagger）、`/openapi.json`

## 通用约定

| 项目 | 说明 |
|---|---|
| 格式 | 请求、回应都是 JSON（UTF-8）；上传图片用 `multipart/form-data`；搜索用 SSE |
| 身份 | 登录后拿到 `token`，之后每个请求带头 `X-Account-Id: <token>`。没带或失效 → 需要登录的接口回 `401 请先登录` |
| 角色 | `reader` 读者（任意邮箱注册）／`sharer` 分享者（验证过北大邮箱，才有人物页、能发文、设时段） |
| 错误 | `{"detail": "中文原因"}`，前端直接显示 `detail` |
| 时间 | 一律北京时间；时段字符串格式 `YYYY-MM-DDTHH:MM`，月份 `YYYY-MM` |
| 限流 | 会花大模型钱的开放接口按 IP 每分钟限次（`SEARCH_PER_MIN` 默认 20、`PARSE_PER_MIN` 默认 10），超过回 `429` |
| LLM 退路 | 大模型不可用（没 key、超时、余额不足）时：搜索退回关键词版、抽取退回「未提及」占位、日历助手回 `503` |

常见状态码：`401` 没登录／`403` 没权限（不是作者、不是分享者）／`404` 不存在／`409` 冲突（时段被约走、已评价过）／`413` 图片太大／`415` 图片格式不对／`422` 参数不合法／`429` 太频繁／`502` LLM 输出格式两次都不对或寄信失败／`503` LLM 不可用

## 1. 账号与登录

| 方法 | 路径 | 登录 | 说明 |
|---|---|---|---|
| POST | `/api/auth/send-code` | 视用途 | 寄 6 位验证码到邮箱 |
| POST | `/api/auth/verify` | 否 | 验证码＋设密码 → 登录（没账号自动注册） |
| POST | `/api/auth/password-login` | 否 | 邮箱＋密码登录 |
| POST | `/api/auth/pku-verify` | 是 | 北大邮箱验证码 → 升级分享者 |
| POST | `/api/login` | 否 | 演示登录：按角色登第一个示例账号（评审免注册） |
| POST | `/api/logout` | 是 | 删掉当前 token |

**send-code**

```json
// 请求
{"email": "a@stu.pku.edu.cn", "purpose": "register"}   // purpose: register | pku_verify
// 回应
{"ok": true, "resendAfter": 60}
```

- `pku_verify` 要登录、邮箱必须以 `@pku.edu.cn` / `@stu.pku.edu.cn` 结尾，且没被别的账号验证过（否则 `409`）
- 同一邮箱 60 秒内只能寄一次（`429`）；验证码 10 分钟有效、只能用一次、错 5 次作废

**verify**（注册／忘记密码）

```json
// 请求
{"email": "a@qq.com", "code": "123456", "password": "至少8位"}
// 回应＝登录态（下同）
{"id": 7, "role": "reader", "name": "a", "email": "a@qq.com", "pkuVerified": false,
 "personId": null, "approved": null, "token": "..."}
```

用北大邮箱走这一步会直接升级成分享者，不用再验一次。

**password-login**：`{"email", "password"}` → 登录态。连续错 5 次锁 15 分钟（`429`）。

**pku-verify**：`{"email", "code"}` → 登录态（`role` 变 `sharer`，`personId` = 新建的空白人物页 `u{账号id}`）。

**login**（演示）：`{"role": "reader" | "sharer"}` → 登录态。

## 2. 文章（经验）

| 方法 | 路径 | 登录 | 说明 |
|---|---|---|---|
| GET | `/api/articles` | 否 | 列表。参数 `category`、`type`、`author`、`lite=1`（不带正文，首页用） |
| GET | `/api/articles/{aid}` | 否 | 单篇，多带 `claims`（保鲜度核验） |
| POST | `/api/articles/extract` | 分享者 | 发布前预览：LLM 从正文抽决策点给作者确认 |
| POST | `/api/articles` | 分享者 | 发布 |
| PUT | `/api/articles/{aid}` | 作者本人 | 改标题／正文 |
| DELETE | `/api/articles/{aid}` | 作者本人 | 删文（决策点、RAG 块、互动一起删） |
| POST | `/api/articles/{aid}/view` | 否 | 记一次阅读 |
| POST | `/api/articles/{aid}/star` | 是 | 点星／取消（切换） |
| POST | `/api/articles/{aid}/bookmark` | 是 | 收藏／取消（切换） |
| GET | `/api/articles/{aid}/helpful` | 否 | 「有帮到我」人数与短评 |
| POST | `/api/articles/{aid}/helpful` | 是 | 按「有帮到我」（再按只更新短评） |
| DELETE | `/api/articles/{aid}/helpful` | 是 | 取消 |
| GET | `/api/trending` | 否 | 热门：`type=article`、`limit=5`，按 30 天阅读人数排 |
| GET | `/api/categories` | 否 | 6 个固定分类（保研、考研、出国、求职、考公、选导师） |
| POST | `/api/articles/{aid}/extract` | — | 开发用重抽，`.env` 设 `DEV_EXTRACT=1` 才开，平常 `404` |

**文章对象**

```json
{
  "id": "12", "authorId": "p3", "date": "2026-10-20", "title": "...", "summary": "...",
  "content": "正文（lite=1 时为 null）", "tags": ["..."], "type": "article", "status": "...",
  "category": "保研", "stars": 3, "bookmarks": 1, "views30d": 42, "readTime": "5 分钟",
  "decisionPoint": { /* 第一个决策点 */ },
  "decisionPoints": [{
    "决策类型": "保研", "学校层级": "985", "专业": "金融", "成绩": "前10%", "年级": "大三",
    "考虑过的选项": ["保研", "出国"], "最后的选择": "保研", "结果": "成功", "结果说明": "...",
    "年份": "2025", "原话": "原文摘句"
  }],
  "claims": []   // 只有单篇有
}
```

**发布**

```json
// POST /api/articles
{"type": "article", "title": "...", "content": "...", "summary": "", "tags": [],
 "decisionPoints": [ /* 作者在预览里确认过的，可省略 */ ], "requestId": "求经验单 id，可省略"}
```

- 作者由登录身份决定，不收前端传的 `authorId`（防冒名）
- 没传 `decisionPoints` → 后端调 LLM 抽；抽不到放「未提及」占位。分类取第一个决策点的决策类型
- 带 `requestId` → 那张求经验单标成「已有人写」，通知所有按过「我想看」的读者
- 写入后同一交易建 RAG 索引；保鲜度核验在背景跑，不拖慢发布
- 回应：完整文章对象

**extract 预览**：`{"title", "content"}` → `{"points": [决策点...], "source": "llm" | "none"}`

**改文**：`{"title", "content", "decisionPoints"?}` → 文章对象。抽不出决策类型时保留原分类；只改标题不重跑保鲜度。

**star / bookmark** → `{"on": true, "stars": 4}`（或 `bookmarks`）

**helpful GET** → `{"count": 3, "mine": false, "comments": [{"name", "comment", "date"}]}`；POST 带 `{"comment": "≤200 字"}`。

**view**：`{"viewer": "前端 cookie 随机 id，可省略"}` → `{"viewer": "..."}`。登录了用账号 id。

## 3. 搜索（multi-agent）

| 方法 | 路径 | 登录 | 说明 |
|---|---|---|---|
| GET | `/api/search/stream` | 否 | 主搜索，SSE 流式 |
| GET | `/api/filters/parse` | 否 | 「AI 帮我选」：一句话 → 筛选条件＋召回文章 id |
| GET | `/api/filters/why` | 否 | 「AI 帮我选」第二步：每篇的推荐理由（红绿灯） |

### `/api/search/stream?q=双非考研&viewer=xxx`

`q` 最长 200 字。回 `text/event-stream`，事件依序：

| event | 时机 | data |
|---|---|---|
| `result` | ①–④ 做完（处境抽取、召回重排、分群），还没经过判断 agent | `{filters, situation, irrelevant, query, results: [文章id], groups: [群], steps, source: "keyword"}` |
| `step` | 每一步完成 | `{step, label, detail, ms}` 检索过程面板一行 |
| `group` | 每群判断 agent 选完代表 | `{id, name, purpose, members: [文章id，代表在前], why: {文章id: {decision_point_id, why, unique, quotes}}}`；`members` 为空＝整群不像，前端拿掉 |
| `review` | 每群审查 agent 审完 | `{id, group, pass: true/false}` |
| `done` | 结束 | `{steps, llmCalls, cachedAt}`（`cachedAt` 非空＝命中缓存） |
| `error` | 出错 | `{error}` |

流程：① 处境抽取（LLM，失败退关键词）→ ②③ RAG 召回＋rerank → ④ 程序分群 → ⑤ 每群一个判断 agent 并行（可调 `get_person_timeline` 工具）→ ⑥ 程序核验引用原话、查不到就删 → ⑦ 审查 agent，不通过打回重判（最多 2 轮）。超时的群维持关键词版。每群都审完才进缓存；发文／改文／删文清缓存。

前端用法：

```js
const es = new EventSource(`/api/search/stream?q=${encodeURIComponent(q)}`)
es.addEventListener('result', e => show(JSON.parse(e.data)))
es.addEventListener('group', e => replaceGroup(JSON.parse(e.data)))
es.addEventListener('done', () => es.close())
```

### `/api/filters/parse?q=...`

```json
{"filters": {"决策类型": ["考研"], "学校层级": ["双非"], "专业": [], "结果": []},
 "irrelevant": false, "results": ["12", "7"], "query": "LLM 改正错字后的检索句", "source": "llm"}
```

### `/api/filters/why?q=...`

```json
{"why": {"12": {"why": "...", "unique": "...", "quotes": ["原话"], "match": "high|mid|low", "hit": 2}}}
```

- `match` 红绿灯：读者条件全对上 `high`、对上至少三分之二 `mid`、其余 `low`；`hit` 对上几条。数数由程序做，模型只判断每条对不对得上
- `quotes` 经程序逐句核对原文，查不到的已删
- 最多 30 篇（每 8 篇一批并行）；LLM 不可用回 `{"why": {}}`

## 5. 预约咨询

| 方法 | 路径 | 登录 | 说明 |
|---|---|---|---|
| GET | `/api/persons/{pid}/slots?month=2026-10` | 否 | 这位分享者这个月还能约的时段 → `["2026-10-25T20:00", ...]` |
| POST | `/api/persons/{pid}/slots/assist` | 是 | 读者用一句话说自己哪时有空 → 跟可约时段取交集 |
| GET | `/api/me/availability?month=` | 分享者 | 自己勾的时段 → `[{t, booked}]` |
| POST | `/api/me/availability/assist` | 分享者 | 日历助手：一句话 → 时段预览（不写库） |
| PUT | `/api/me/availability` | 分享者 | 整月覆盖储存；已被约的拿不掉 |
| POST | `/api/bookings` | 是 | 预约 |
| GET | `/api/me/bookings` | 是 | 我约别人的 |
| GET | `/api/me/incoming-bookings` | 分享者 | 别人约我的（只给读者显示名，不给邮箱） |
| POST | `/api/bookings/{bid}/paid` | 预约人 | 标记已付款（平台不经手钱，通知分享者去微信核对） |
| POST | `/api/bookings/{bid}/complete-review` | 预约人 | 评价 `{stars: 1-5, comment: ≤500 字}`，一笔只能评一次 |

**预约**

```json
// 请求
{"personId": "p3", "minutes": 40, "startsAt": "2026-10-25T20:00", "question": "..."}
// 回应
{"id": "5", "personId": "p3", "mentorName": "...", "duration": 40, "slot": "2026-10-25（周六）20:00",
 "price": 99, "question": "...", "status": "...", "paid": false, "payQr": "/uploads/...", "review": null}
```

- `minutes` 只能 20 或 40；价格以库里为准，不信前端
- 时段不在可约清单 → `409`；两人同时约同一时段，唯一索引保证只成功一个，另一个 `409`

**日历助手**

```json
// POST /api/me/availability/assist
{"month": "2026-10", "text": "周末晚上八点到十点", "current": ["2026-10-25T20:00"]}
// 回应
{"slots": ["2026-10-25T20:00", "2026-10-25T21:00"], "note": "...", "ask": null}
```

没说几点会回 `ask`（反问几点），不会自动开满 24 小时。`slots/assist` 回 `{matches, note, ask}`。

**PUT /api/me/availability**：`{"month": "2026-10", "slots": ["2026-10-25T20:00", ...]}` → 同 GET 回应。

## 环境变量（`.env`，范例见 `.env.example`）

| 变量 | 用途 |
|---|---|
| `DATABASE_URL` | PostgreSQL 连线 |
| `LLM_API_KEY`、`LLM_BASE_URL`、`LLM_MODEL`、`LLM_THINKING` | 大模型（DeepSeek，OpenAI 兼容）；没 key 时全部退关键词版 |
| `SILICONFLOW_API_KEY`、`SILICONFLOW_BASE_URL`、`EMBEDDING_MODEL`、`RERANK_MODEL` | RAG 的 embedding／rerank |
| `SEARCH_LLM_PARSE=1` | 搜索第①步用 LLM 抽处境 |
| `SEARCH_RAG`、`SEARCH_CACHE_TTL` | 搜索召回方式、agent 结果缓存秒数 |
| `AGENT_TIMEOUT`、`LLM_TIMEOUT`、`LLM_CONCURRENCY` | agent 总超时、单次 LLM 超时、同时打 LLM 的上限 |
| `SEARCH_PER_MIN`、`PARSE_PER_MIN` | 限流次数 |
| `SMTP_HOST`、`SMTP_PORT`、`SMTP_USER`、`SMTP_PASSWORD` | 寄验证码 |
| `DEV_EXTRACT=1` | 开启开发用重抽接口 |
| `AUTH_ALLOW_ID=1` | 只给测试：`X-Account-Id` 可直接放数字账号 id |
